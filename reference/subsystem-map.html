Reference · How Elicit Works

Subsystem Map

One line per top-level directory in src/. Grouped by which of the five big roles it mostly serves — see Lesson 1 for the loop these roles form. Term definitions live in CONTEXT.md; this table is a locator, not a glossary.

Elicitor-side (the live sitting)

DirectoryJob
elicitor/Runs the live turn: starts sessions, handles answers, picks the next question, enforces guards.
protocols/The registry of question Protocols (episode probe, triadic construct elicitation, critical decision method, ...) and their definitions.
queue/The durable store of pending questions — what survives between sittings, and how it's drawn from (facet balance, source labels).
randomizer/Serendipity draws from forgotten Snippets or curated decks — shuffles, never invents.
sounding/The consent-gated descent ladder (budget, gate, park/resume, convergence) for deep chained questioning.
drm/The Day Reconstruction Method instrument — a specific structured episodic-recall protocol, implemented as its own state machine.
patterns/The library of derivation patterns for composed questions (cheap tier vs. Sounding-class deep tier).

Harvester-side (turning prose into evidence)

DirectoryJob
harvester/Proposes cuts of your prose into Snippets; you approve, trim, discard, or restate.
import/Seeding — bringing in pre-existing corpora (journals, notes) incrementally: survey, reach, extract, adopt, commit, repair.
ktg/Territory instruments — a stored map of a domain or life (skeleton coverage, atlas coverage/validation) tracking corpus coverage as a private checklist, never a shown score. (The gazetteer — person/entity index — is a separate clerk/ concern, not ktg/.)

Vault-side (storage)

DirectoryJob
vault/The archive itself — plain markdown with frontmatter, its own git repo, immutable Snippet versions.
index/Lexical and semantic (embedding) search over the vault — what makes Resonance possible.
log/The append-only Activity Log — every deterministic and agentic event, visible on the interface as the audit trail.

Clerk-side (background work)

DirectoryJob
clerk/The background role itself: the Docket (standing task pipeline — composing, sweeping, consolidating; see Lesson 1), contradiction detection, question minting, arrangements, annotations, the gazetteer (person/entity index), the lineage-mirror shadow sweep.
memory/Consolidation across sittings — the three-layer memory scheme (ADR-0002), session summaries.

Wiki-side (the model of you)

DirectoryJob
wiki/Claims, citations, contradiction thresholds, the claim registry, clash detection, lint rules, status/coreness computation.

Composition and standalone concerns

DirectoryJob
piece/Composed documents built by stacking Snippets — Arrangements, Gaps, staleness, dormancy, markdown export.
coach/Per-capability advice role — quest log, doing-quests, event-licensed (never time-licensed) advice.
auth/Password auth (scrypt-hashed), loopback-only checks.
stt/Speech-to-text — Parakeet running in-process via sherpa-onnx, so dictation never leaves the machine.
This table will drift as the codebase does — it was written 2026-08-03 against the state after the person-model campaign (five waves, commit ed64287). If a directory's job here doesn't match what you find in the code, trust the code and update this table.
